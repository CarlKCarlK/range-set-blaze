## What was added

| Operation | Streams (`SortedDisjointMap`, `MultiwaySortedDisjointMap`) | Struct (`RangeMapBlaze`, `[&maps]`) |
|---|---|---|
| Inner join: ranges covered by both | `a.inner_join(b)` -> `(range, (VCL, VCR))` | `a.inner_join(&b)` -> `RangeMapBlaze<T, (V, V2)>` |
| Left join: ranges covered by the left | `a.left_join(b)` -> `(range, (VCL, Option<VCR>))` | `a.left_join(&b)` |
| Full join: ranges covered by either | `a.full_join(b)` -> `(range, (Option<VCL>, Option<VCR>))` | `a.full_join(&b)` |
| Transform values | `stream.transform_values(f)` -> `(range, Owned<W>)` | `map.transform_values(f)` -> `RangeMapBlaze<T, W>` |
| Multiway inner join | `[s1, s2, ...].inner_join(\|values: &[VC]\| ...)` | `[&a, &b, ...].inner_join(f)` |
| Multiway full join | `[s1, s2, ...].full_join(\|values: &[Option<VC>]\| ...)` | `[&a, &b, ...].full_join(f)` |
| Multiway sweep | `[s1, s2, ...].sweep()` -> `SweepEvent::Start`/`End` | none (low-level) |
| Universe constructors | none | `RangeMapBlaze::universe_with(&v)`, `RangeSetBlaze::universe()` |

Supporting additions: `Owned<V>` (a by-value `ValueCarrier`, in the prelude), `ValueCarrier` for
pairs `(VCL, VCR)`, and the iterator types `InnerJoinMap`, `LeftJoinMap`, `FullJoinMap`,
`TransformValuesMap`, `MultiwayInnerJoinMap`, `MultiwayFullJoinMap`, `MultiwaySweep`, and
`SweepEvent`.

## Design principles

- **Iterator-first.** Every operation is a stream operation; the `RangeMapBlaze` form is a thin
  wrapper, `self.range_values().op(...).into_range_map_blaze()`.
- **Opaque, operation-named result types.** Results of public operations are named structs with
  private fields, as in std (`btree_set::Union`), so implementations can change without changing
  types. Names follow the operation; `Map` marks a map stream and `Multiway` marks k inputs:
  `Union`, `Intersection`, `Difference`, `SymmetricDifference`, `MultiwayUnion`,
  `MultiwayIntersection`, `MultiwaySymmetricDifference`, `UnionMap`, `IntersectionMap`,
  `DifferenceMap`, `SymmetricDifferenceMap`, `NotMap`, `MultiwayUnionMap`,
  `MultiwayIntersectionMap`, `MultiwaySymmetricDifferenceMap`, plus the join and transform types
  above. These replaced `#[doc(hidden)]` aliases that exposed internals (`UnionMerge`,
  `SymDiffKMergeMap`, ...); the released old names remain as deprecated aliases. The wrappers are
  generated by one macro in `src/operation_results.rs`. Building-block types (`UnionIter`,
  `NotIter`, ...) keep their names.
- **Values are cheap to clone.** Operations clone a value whenever they split its range; large
  values belong behind `Rc`/`Arc`. Now stated in the `RangeMapBlaze` docs.
- **Special-case code only where it measurably pays.** Otherwise share one implementation (the
  sweep), so it gets more testing through use.
- **Output is canonical.** Joins and transforms merge touching ranges whose results are equal, so
  every result is a valid `SortedDisjointMap`.

## Joins

**Item shapes.** Pairs of carriers, with `Option` for a side that may be absent; no new enum. The
full join never yields `(None, None)`. When both inputs are universal (cover every key), the inner
and full joins agree; `range-map-regex` relies on this, since every DFA transition map is total.

**Left join.** Not just a filter on the full join: it stops as soon as the left input ends,
without reading the rest of the right input. That matters for "is every left range covered?"
(glrmask's `is_subset`). No `right_join` (swap the inputs) and no multiway left join (expressible
as a multiway full join with a check on `values[0]`).

**Naming.** `inner_join` is standard. "Outer join" names a family (left, right, full), so the full
join is `full_join` (renamed from `outer_join` before release, when `left_join` was added). The
multiway joins share the two-way names; their receivers differ (`a.inner_join(b)` versus
`[a, b, c].inner_join(f)`), so Rust has no conflict.

**Multiway closures.** One call per maximal stretch over which the inputs' values are constant, in
key order, so `f` may be `FnMut` and keep state. The inner join passes `&[VC]` (every input
present); the full join passes `&[Option<VC>]` (one value per input, in input order, never all
`None`). The slice is borrowed from a buffer updated in place, never rebuilt, and no `V` is
cloned. With zero inputs, the full join is empty and the inner join is the universal range with
`f(&[])`, matching `RangeSetBlaze`'s zero-input intersection. A slice beats an iterator argument
(`len()`, indexing, repeat iteration) and positions beat present-values-only (users ask "what did
input 2 contribute?").

**`left_join` evidence and its test.** Written as `full_join(...).all(...)`, glrmask's
`is_subset` kept walking every remaining range of `other` after `self` ended (found in review).
`left_join` has a test that a small left input against 10,000 right ranges reads at most 3 of them.

## `transform_values` and `Owned`

Renamed from `map_values` before release: in a crate whose main type is a map, "map" reads as the
noun. `f` is called once per range in key order; equal touching results merge; the struct form
keeps `len`.

The stream form needs a carrier for values the closure creates: `&W` has no owner to borrow from,
`Rc<W>` allocates per range, and a blanket `impl ValueCarrier for V` would overlap the existing
impls (and users cannot implement the trait for std types, by the orphan rule). Hence `Owned<V>`:
holds its value inline, cheap to clone exactly when `V` is (use `Owned<Rc<X>>` for large values),
transparent `Debug`, and collecting a stream of `Owned<V>` gives `RangeMapBlaze<T, V>`. Named after
std's `Cow::Borrowed`/`Cow::Owned` contrast. A `Cow<'a, V>` carrier is possible and additive;
deferred.

## The multiway sweep

`sweep()` yields each input range's start (with range, input position, and value, moved rather
than cloned) and end (last key, input position) in key order; a range ending at `p - 1` ends before
one starting at `p` starts. It is the primitive under the multiway joins and under the moved
multiway operations below, and it is public for power users (overlap depth, running aggregates,
custom precedence).

It replaced `outer_join_incremental` (removed before release), which gave the closure the inputs
that changed since its previous call. That closed a measured gap (a closure aggregating over all
present values pays O(present) per range; an incremental one pays O(changes)), but glrmask's union
written directly on `sweep` was faster at every size and the contract is simpler.

**Engine.** A binary heap of small `(start, input)` keys, with iterators and pending ranges kept in
place (the top is replaced in place when an input's next range arrives), plus a heap of
`(end, input)` for active ranges. O(log k) per input range. Versus `itertools::kmerge_by` (whose
heap entries hold whole iterators), ordering by start was 0.60-0.90x at 4-512 inputs, about even
at 3, and 1.15x at 2 with borrowed values; whole operations built on the sweep were still about 2x
faster at 2 inputs, so there is no special case. Ties at the same start come out in input order.

## Existing operations moved to the sweep

Each candidate was prototyped and timed in the same test binary as the released code (comparing
two separate builds proved misleading: code layout made an unchanged operation look 20-70% faster).

| Operation | Sweep time / released time | Decision |
|---|---|---|
| multiway map `union` | 0.24-0.71 | moved |
| multiway map `symmetric_difference` | 0.23-0.67 | moved |
| multiway map `intersection` | released 1.2-3.3x faster on dense inputs | kept |
| two-way map `\|`, `^` (with a crate-private `EitherMap` for two input types) | 0.35-0.63 | moved |
| multiway set `union`, `intersection` | mostly slower (0.84-1.99) | kept |
| multiway set `symmetric_difference` | 0.65-0.96; 1.05-1.23 at 2-4 sparse inputs | moved (shared code accepted over the small-k loss) |
| two-way set `\|`, `^`, `&` | slower (0.99-4.06) | kept |

Set code carries no values, so its released merges are already lean. Sets enter the sweep through
a crate-private adapter that gives every range the value `true`. Map semantics are unchanged: kept
when at least one / an odd number of inputs are present, with the value of the highest-numbered
input present.

Removed, since nothing used them and they never had public constructors: `KMergeMap`, `MergeMap`,
`SymDiffIterMap`, and the crate-private `SetPriorityMap`.

## Tests

Brute-force per-key oracles under quickcheck (checked with 20,000 cases) for the multiway joins,
the sweep's event contract, and multiway map and set union/intersection/symmetric difference;
exhaustive small-input oracles for the two-way joins; call-order, merging, zero-input, and
maximum-key tests; trait checks (Send, Sync, Unpin, Clone, Debug, FusedIterator) for the new
public types; and the `left_join` early-stop test.

## Real-world checks

- **range-map-regex** (`src/dfa.rs`): DFA product constructions use
  `range_values().inner_join(...).transform_values(...)` on streams, `concat` and
  `subset_transition_map` use one multiway `inner_join`, and `minimize`/`star` use
  `transform_values`. Its earlier local `map_values` helper and pairwise folds are gone. Ports were
  checked by byte-identical example output, including DFA state numbering.
- **glrmask** (fork `CarlKCarlK/glrmask`, branch `local-rsb`): its two-way union and combine use
  `full_join`, `is_disjoint` uses `inner_join`, and `is_subset` uses `left_join`, with exhaustive
  differential tests against the originals; all RSB-related glrmask tests pass. A multiway union
  rewrite on `sweep` was faster at 8-128 weights (0.65-0.87x) but was reverted as not worth it
  there. glrmask also compiled unchanged against this branch after being written for 0.3.0.

## Open questions

- **Collect-and-sort engine.** Reading all ranges into one array and sorting once was about 6x
  faster than the streaming heap at 512 inputs (309 us versus 1,825 us), but uses O(total ranges)
  memory and is not lazy. Possible split: streams stay streaming; struct forms (which build a whole
  map anyway) use collect and sort. Not decided.
- **Deferred until a caller appears:** a filtering transform (workaround:
  `transform_values` to `Option`, `filter`, `transform_values` to unwrap, all lazy), a `Cow`
  carrier, a multiway left join, and owned-maps forms of the multiway joins
  (`[a, b].inner_join(f)` on `MultiwayRangeMapBlaze`).
